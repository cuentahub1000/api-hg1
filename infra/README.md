External: hg.cash API (`PROVIDER_API_URL`, production `https://hg.cash/api/v1`),
one hg.cash account (`PROVIDER_ACCOUNT_ID`) that collects checkouts and pays
transfers; webhook URL + signing secret are registered in its dashboard.

## Order of deployment

`cdk deploy --all`: database → webhook → other functions (they read the
webhook URL from SSM) → resource group → `migrate` invoked by the npm script.
Every SSM value a function uses is resolved by its own stack at deploy, so a
changed parameter redeploys the functions and nothing else.
`deploy:all` in `cdk/package.json` does all of it.

## Not here

No Redis, no SNS, no API Gateway. The provider reaches the webhook through a
Lambda Function URL (or `provider-webhook-url` when an ingress fronts the HTTP
runtime). The wallet database is never touched.
